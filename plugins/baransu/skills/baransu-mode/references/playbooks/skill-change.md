# Skill change — a SKILL.md, an agent prompt, an instruction or rules file

**You own every copy of the text. The steps do the work.**

1. `/how` over the skill and every file that reads it or restates it, mirrors included.
2. `/why` for each clause the change rewrites or removes.
3. [the change is undecided, or a skill is to be added or retired] `/think`, then wait for the user's go on the plan.
4. Edit the text and every copy that mirrors it in the same change; or [the goal is a scored improvement against a rubric] `/evolve` instead of editing by hand.
5. Run the repo's structural checks and the skill's eval set where they exist; quote their output.
6. `/review` of the change.
7. [the authorization names a version-control endpoint] `/ship` with the targets the user named.

**Reply:** what changed and why, every mirror touched, the check and eval output, the review verdict.
