## `/think`

Claude Code：`/baransu:think`　Codex：`$baransu:think`

**用途**　動手前審議：先復述你要的東西對焦，借鏡已經解過這類問題的學門（有數量在手時照 `_shared/modeling.md` 建模、用白話陳述），表態並答三題——目標背後的目標、方案的一個主意、成本對效果——查證前提，兩向攻擊，呈現，落一份五段計畫到 `.claude/think/`。不寫程式、不交棒；已定的決定也可拿來拷問。

**什麼時候用**
- 有一個還沒決定的點子、功能、重構或方向，想問怎麼設計、走哪條路、值不值得做。
- 觸發語：想一下、幫我想、怎麼設計、值不值得、該不該做、「我想做 X 但還不確定」。
- 已經做好的決定想被拷問：拷問我、grill me。
- 存廢判決（Kill / Keep / Pivot）也在這裡做——`/hunt` 的「值不值得修」、`/evolve` 的「這個 skill 該不該存在」都轉來這裡。

**流程**　對焦復述 → 借鏡（長命功能、核心路徑、方向題、存廢判決必做；參數選擇、單檔小修略過並說明）→ 表態並點名押注 → 查證前提（每條標「已查證」或「未實查」）→ 兩向攻擊（會壞在哪，追一個情境到底；尺寸——做過頭或做太小）→ 用一般人看得懂的方式呈現 → 落計畫檔後停。

**產出**
- 對話中：確認過的復述、立場與押注、前提查證標記。
- 可落地的工作：`.claude/think/<slug>.md`，最上面是復述，下面五段計畫；成功條件是可檢查的條件而非時長，切成多片時第一片指名為 pilot。
- 判決（Kill / Pivot）或拷問既有決定：只給立場，不寫計畫檔。
- `/ship` 收工時會歸檔 `.claude/think/`。

**不適用**
- 排查既有錯誤 → `/hunt`
- 已定案的中型工作 → 直接實作（`_shared/tdd.md` 紅綠紀律），再 `/review`
- 單檔小修 → 直接實作，照 `_shared/tdd.md` §7 的紅綠紀律

**非互動驅動**　`loop=not-drivable`（需要使用者確認復述，不適合 /loop、cron、Workflow 無人驅動）。
