# Hypothesis

A change that reaches what a hypothesis covers either keeps every rule of that hypothesis 守住 within its scope, or the review says which rule it puts at stake and why. A hypothesis is the author's machine-checked evidence, read like a test record: the review reads its README, never runs or edits it.

**Why:** A hypothesis states, for every order of steps its model allows, what must never happen and what must stay possible. Its value lasts only while it describes the code: once what it covers changes, a pass describes code that no longer exists, and that pass is a false proof. The reviewer is the one reader who sees the change and the claim side by side, so it is where a broken or forgotten hypothesis is cheapest to catch.

**Pattern:**
1. **Read the README first.** For each area under `.codex/hypothesis/`, read what its README says it covers (file and symbol) and the version it describes; the hypothesis covers this change when the change touches one of those files. Quote the area, its coverage and its version. Reading files runs no target, so it stays inside review-only.
2. **Put the coverage on the walk.** Every place a covering hypothesis cites goes on the walk, and each of its rules (the README's rule table) becomes that place's question: after this change, does the rule still hold here? Answer from the code, with the rule's id.
3. **Changed since its version is not evidence.** A hypothesis whose covered code changed after the version its README names — in this change or before it — was checked against code that is no longer there, so it is not a record of this version (`evidence.md` #2). Write 「假說 {area} 描述的是 {version}，涵蓋的程式之後改過，要重跑或 `$baransu:hypothesis --maintain {area}` 才能當證據」: as the impact of a problem headed per `index.md` where the author relies on it, otherwise as an uncertain item. Ask its rules as questions anyway. Maintaining it is the main session's call into `$baransu:hypothesis`, never this review's.
4. **Known paths stay known.** For a hypothesis with a rule 被打破, each path (`paths/P<n>.md`) is an existing finding: say whether the change fixes it, touches it, or leaves it, with the path id.
5. **Review a hypothesis as a target.** When the target is a hypothesis itself: its rules match what the user asked (`goal.md` #7 — a hypothesis is a plan of what must hold), and each item of `/hypothesis`'s Done when holds: the ideal and the rules written before any answer, the rules confirmed or marked 未經確認, the ledger closed with the two bounds and the gap stated, the kind named and its judge written before any answer code and calibrated, premises marked 實測, 讀出 or 假設, the answer frozen with its hashes and verified once, the sealed second derivation compared; each model part cites its source and keeps the source's indivisible steps; bounds, assumptions and what is left out are stated; each finding opens in plain words.
6. **Read, never reproduce.** Do not rerun the model, run the README's commands, or edit anything under `.codex/hypothesis/`; a claim only a rerun can settle goes to `$baransu:prove-it`.
7. **Scope is part of the proof.** A rule that holds within the stated bounds says nothing outside them (`evidence.md` #9 for a model); a place the change reaches outside the scope needs its own evidence.

**The test:** For each hypothesis whose README covers a file the change touches: are its coverage and version quoted, does every place it covers carry its rules as questions, and is each one whose covered code changed after its version reported rather than trusted?

**You skipped this when** the review passed a change to code a hypothesis covers without quoting its README's coverage and version, or accepted 「規則都守住」 from a hypothesis whose covered code changed after the version it names.
