# HUNT-2026-002 — Codex hook 三項契約黑箱驗證

## 症狀

已安裝的 Codex mirror 宣稱 `seal-guard` 可在 Stop 階段阻擋結束，但腳本輸出
`{"continue":false,...}`，且以 `PLUGIN_ROOT` 判斷 runtime。需用官方契約與
本機 Codex CLI 實驗確認三項假設。

Locate：
- Event sequence：Codex agent 完成 turn，觸發 `Stop` lifecycle hook。
- Reproduction data：現有 `seal-guard.sh`、Codex `hooks.json` 與最小 synthetic hook。
- Dirty-data characteristic：舊分支輸出 PostToolUse schema；project hook 未必有 plugin env。
- Environment：本機 Codex CLI 0.145.0（WSL2）；Windows 專屬命令以可用 Windows CLI 補測，否則明列未實測。

建立時狀態原文：`status: scoping`

## 調查記錄

### 假說 1
- 假說：Codex hooks 預設啟用，且解析 `commandWindows`。
- 工具（帶 `🎯HUNT-2026-002` tag）：官方 manual + 最小 CLI hook probe。
- 結果：Linux 未設定 `features.hooks=true` 仍命中 project Stop hook；Windows
  Codex 0.145.0 在 POSIX `command` 故意 `exit 88` 時，仍由 `commandWindows`
  寫出原樣證據：`HUNT-2026-002 commandWindows-ran`。
- 保留或丟棄：保留；hooks 預設啟用且 Windows override 實際生效。

### 假說 2
- 假說：`continue:false` 無法阻擋 Stop，`decision:block` 才能阻擋。
- 工具（帶 `🎯HUNT-2026-002` tag）：同一 CLI 流程只替換 hook stdout。
- 結果：`continue:false` 只命中 1 次 Stop；`decision:block` 命中 2 次，
  第二次 stdin 原樣含 `"stop_hook_active":true`。Codex JSONL 前者只有一個
  `FIRST_PASS` agent message，後者有兩個。
- 保留或丟棄：保留；`decision:block` 才建立 continuation prompt。

### 假說 3
- 假說：project-level hook 不會收到 `PLUGIN_ROOT`，plugin-bundled hook 才會。
- 工具（帶 `🎯HUNT-2026-002` tag）：兩種 hook source 的環境快照，只記錄變數存在性。
- 結果：project hook 原樣記錄
  `plugin_root=unset claude_plugin_root=unset`。另一方面，已安裝
  `baransu@baransu` 的 plugin-bundled command 使用 `${PLUGIN_ROOT}` 才能解析
  `seal-guard.sh`；隔離 repo 實際寫出 `seal-miss` telemetry，且
  `/hooks/seal-guard.sh` 不存在，證明 plugin command 收到 root。
- 保留或丟棄：保留；但目前 baransu 是 plugin-bundled，不是 project-level，
  所以此事不會推翻目前 `PLUGIN_ROOT` discriminator。

## 根因分析

根因是 `plugins/baransu/hooks/seal-guard.sh:88` 的 Codex 分支輸出
`continue:false`，因為既有測試只驗證腳本吐出指定 JSON，沒有把它接進真正
Codex Stop lifecycle；Codex CLI 0.145.0 對 Stop 只有
`{"decision":"block","reason":"..."}` 會建立 continuation prompt。

官方 Hooks 頁本身容易誤讀：Common output 列出 `continue:false`，但 Stop
專節明確說 `decision:block` 才是「keep Codex going」，而
`continue:false` 會優先壓過 continuation decisions。黑箱結果與 Stop 專節一致。
來源：`https://learn.chatgpt.com/docs/hooks.md#stop`。

`PLUGIN_ROOT` 的適用範圍則沒有產品 bug：project-level 探針確實拿不到，但
目前安裝紀錄與 trust key 都把 baransu hook 識別為
`baransu@baransu:hooks/hooks.json`，屬 plugin-bundled source。
