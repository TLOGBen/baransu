# HUNT-2026-001 — skill 本體 CLAUDE_PLUGIN_ROOT 漏轉

## 症狀

Plugin transfer 後，來源 skill（使用者觀察為 delegate）本體中的
`${CLAUDE_PLUGIN_ROOT}` 原樣留在 Codex `SKILL.md`；agent 與 hook 路徑則會改寫。

Fast Path：首儀器定根因 ✓；blast 候選 21，真正修復點 2 ≤3 → 壓縮儀式。

Locate：
- Event sequence：執行 plugin mode transfer 後讀取生成的 skill 本體。
- Reproduction data：`Use ${CLAUDE_PLUGIN_ROOT}/skills/example/...`。
- Dirty-data characteristic：token 位於 SKILL.md/references，而非 bundled agent 或 hook command。
- Environment：純 Python/static transformation，可在本機測試重現。

建立時狀態原文：`status: scoping`

## Before You Fix

### 呼叫鏈分析
- 直接呼叫者：`transfer_one` → `rewrite_body`；plugin mode 再由 `transfer_plugin` 呼叫 `transfer_one`。
- 業務場景數：single skill、skills batch、plugin mode 三條均共用 skill-body rewrite。
- 高風險點：文件中談論 Claude token 的字面例句不可被盲改；runtime skill/reference 則不可留下失效變數。

### 測試矩陣

| 維度 | 值 | 必須覆蓋 |
|------|---|---------|
| 位置 | SKILL.md body | 是 |
| 位置 | references runtime instruction | 是 |
| 位置 | bundled agent | unchanged，既有覆蓋 |
| 位置 | hook command | unchanged，既有覆蓋 |
| 語境 | mapping documentation literal | 必須保留或明確 exempt |

## 調查記錄

### 假說 1
- 假說：skill-body pipeline 沒有任何 `CLAUDE_PLUGIN_ROOT` rewrite，closure validator 也不掃 skills。
- 工具（帶 `🎯HUNT-2026-001` tag）：直接呼叫 `rewrite_body`，再以 source/generated/cache grep 交叉確認。
- 結果：直接 probe 原樣輸出 `🎯HUNT-2026-001 Use \`${CLAUDE_PLUGIN_ROOT}/skills/helper/SKILL.md\`.`；官方 Codex manual 只把 `PLUGIN_ROOT` 保證給 plugin hook commands，沒有保證 skill body 執行環境有該變數。
- 保留或丟棄：保留，已由 transformation output + 官方 runtime surface 兩層交叉確認。

## 根因分析

根因是 `rewrite_body()` 沒有處理 `CLAUDE_PLUGIN_ROOT`，因為唯一的路徑
rewrite 位於 `rewrite_bundled_agent_instructions()`（只被 bundled agent 呼叫）
與 hook command translation；同時 `validate_plugin_content_closure()` 的
forbidden-token scan 只涵蓋 `.codex-agents/*.toml` 與 `rules/*.md`，所以
SKILL.md 與 references 既不改寫也不被 closure gate 擋下。

不能把 skill body 盲換成 `PLUGIN_ROOT`：目前官方 manual 僅保證 plugin hook
commands 收到 `PLUGIN_ROOT` / `PLUGIN_DATA`。Transfer 應保留 token 並把
SKILL.md／reference 逐檔列入人工檢視，由移植者依實際 package layout 決定；
mapping 文件中的字面教學例句也因此不會被破壞。

## 修復

`codex-skill-transfer` 0.14.2 新增兩個 flag-only 檢查面：

1. `TOKEN_SCAN_PATTERNS` 加入 `CLAUDE_PLUGIN_ROOT`，涵蓋 references 與 plugin
   shared aux。
2. `transfer_one` 在 body rewrite／adapter injection 後掃描生成的 `SKILL.md`，
   命中時逐檔列入需人工檢視。

兩者都保留 token 原文，不改寫成未受 skill runtime 契約保證的 `PLUGIN_ROOT`。
