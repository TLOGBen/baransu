# tradeoffs — 我們接受 X，換到 Y

## 接受的

1. **我們接受**多一層：讀一次執行要經過 SKILL.md → `ports.md` → 一個來源 adapter → 一個工具 adapter；**換到**新增一種工具或一種來源，只要加一個檔案（加一個 `STALE` 函式），核心的九個步驟一個字都不用改。SKILL.md 第 0 步明講「只載入綁定的那幾個 adapter，最多三個」，所以每次實際要讀的檔案數是固定的。

2. **我們接受**每個 adapter 都要寫滿固定的十節（來源）或九節（工具），就算某節只有一句話；**換到**「漏了一節」可以被結構驗證器抓到（可以加進 `verify-skills.py`：每個 `sources/*.md`、`tools/*.md` 的 H2 必須等於 `ports.md` 的表）。這是把規則改成結構，符合 CLAUDE.md「先用結構」。

3. **我們接受** `pair` 是組合型 adapter，不是第三種葉子；**換到**「文件對文件」「程式對文件」「程式新版對舊版」三種對照共用一份檔案，精化檢查只寫一次。

4. **我們接受**文件子類型（RFP、SA、SD、訪談）只是 `document.md` 裡的一列，不是 adapter；**換到**不出現五個幾乎一樣的檔案。代價是 pull 說的「一種新文件 = 一個新 adapter」只在引用或同步方式真的不同時才成立（BPMN、OpenAPI）。我認為這才是 port 的正確邊界：差異只在「先找什麼」，就不值得一個接縫。

5. **我們接受**多一支 Python 腳本（`hypothesis-status.py`），而這個 repo 一般偏好純 Markdown；**換到**「過期」只有一份程式在算，`/prove-it`、紅綠綠燈、`/review`、`/health` 四處呼叫同一個函式。這直接對上計畫的成功標準「四處都回報過期，沒有一處回報通過」。hunt 已經有 `hunt-search.py` 這種先例，Codex 也能跑。

6. **我們接受** `stale` 永遠不存，每次都要算（一次 `git diff` 加幾個雜湊）；**換到**不會有「檔案說新鮮、其實過期」的狀態。

7. **我們接受**第一版只收錄 `tlc` 和 `kani` 兩個工具 adapter，其他工具一律回「無法寫成假說：adapter 未收錄」；**換到**每個收錄的 adapter 都跑過已知答案考題，不會出現一份寫得很像、其實沒跑過的 Dafny 指南。這兩個剛好涵蓋工具 port 的兩種形狀（轉移系統、直接驗程式），所以接縫今天就有兩邊。

8. **我們接受**在 `sources/` 存一份文件的 Markdown 快照（等於複製了使用者的文件）；**換到**兩件事：引用可以機械檢查（原文必須逐字出現在快照裡），維護時可以拿新版跟快照比對差異。

9. **我們接受** staging 目錄加 `revision` 比對，寫入流程變長；**換到**讀者永遠看不到寫到一半的假說，兩次執行撞在一起時不會互相覆蓋。

10. **我們接受**從 `prove-it/formal/` 搬過來的檢查一律從 `draft` 開始，直到補上「看過它成功」和圖組；**換到**舊檢查不會因為搬家就被當成符合新的嚴格標準。代價：搬家後 `/prove-it` 會先看到一段時間的「草稿」，而不是以前的「通過」。

11. **我們接受**反例有 `path` 和 `witness` 兩種形狀，圖組要會畫兩種；**換到** H7 的結果不用硬塞進狀態圖，照樣說得清楚。

12. **我們接受** `loop=not-drivable`，跟計畫一樣；**換到**沒有 loop-pauses 檔，Gate 10 不受影響。規則確認和看圖本來就是給人做的。

## 考慮過、放棄的

| 選項 | 為什麼放棄 |
|---|---|
| 每種語言一個來源 adapter | `file:line` 對所有語言都一樣；語言只影響工具能力，放在 § Capability 就夠 |
| hunt 症狀當成一種來源 | 症狀不需要引用方式或同步點；它是主張的起點。改成 `--seed` |
| 讀者各自用文字描述過期規則 | 四份文字一定會飄；計畫要的是結構上的保證 |
| 把 `stale` 寫進 README，由 hook 或 maintain 更新 | 沒有任何寫入者能知道來源什麼時候被改 |
| 工具 adapter 寫成 Python 外掛（每個工具一個 class） | 選工具和寫模型需要判斷，Markdown 能承載；只有過期需要能執行 |
| 一次把 Verus、Dafny、SMT、TLAPS 全寫成 adapter | 本機沒裝、沒有考題，等於假想的接縫 |
| 圖的繪製器也做成 port | 只有 Mermaid 一個 adapter；`/draw` 由人手動叫用 |
| 用一個 `index.md` 列出所有假說給讀者查 | 跟各 README 是兩份副本，會不一致；腳本直接掃 README |
| 搬家時舊位置留一份副本 | 兩個位置會分岔；用 `git mv`，一個 area 只有一個位置 |
| 改壞的版本直接改在使用者的工作樹再還原 | 跑到一半停掉就會留下壞掉的產品程式碼 |
