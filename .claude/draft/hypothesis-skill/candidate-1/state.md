# state — 每份狀態歸誰，兩個人同時寫、跑兩次、停在半路會怎樣

## 誰擁有什麼

| 狀態 | 在哪 | 唯一的寫入者 | 讀者 |
|---|---|---|---|
| area 目錄整份（README、模型、page.html、evidence/） | `.claude/hypothesis/<area>/` | `/hypothesis`，而且只在 §6 交換那一刻 | 腳本；人 |
| 儲存的判定 `verdict`、每條規則的狀態 | README front matter | `/hypothesis` | 腳本 |
| 同步點（`covers` 的 blob hash、`sync` commit） | README front matter | `/hypothesis`，只在看過它失敗之後 | 腳本（過期判斷只看 blob）、`--maintain`（diff 起點） |
| 「過期」「舊位置」「與紀錄不符」 | **不存檔**，每次由腳本算 | 沒有人寫 | 所有讀者 |
| 重跑的結果 | 不寫回 area；讀者寫進自己的紀錄 | `/prove-it` 的 `records/`、hunt 的案件檔 | 各自的讀者 |
| 寫入中的草稿 | `.claude/hypothesis/.<area>.draft/` | `/hypothesis` | 腳本只用來判斷「寫入中 → 過期」 |
| 舊位置的形式檢查 | `.claude/prove-it/formal/<area>/` | 8.15.0 的 `/prove-it` 寫的；搬遷時由 `/hypothesis` 在使用者同意後搬走並刪除 | 腳本（`舊位置`）、`/prove-it`（搬遷前照舊） |
| 「使用者說不要寫」的一行原因紀錄 | 讀者自己的輸出（hunt 案件檔、review 報告） | 那個讀者 | 人 |

「過期」不存檔是這個形狀最重要的一條：存檔的過期旗標需要有人在程式改動時去更新它，而那正是會被忘記的事。由讀的那一刻計算，就沒有人能忘。

## 兩個寫入者

**同一個工作目錄、兩個 session 同時對同一個 area 跑 `/hypothesis`**：各自寫自己的 `.<area>.draft/`（名稱撞了→第二個看到既有草稿就停下來回報，不覆蓋）。交換是 rename，後交換的贏；先交換的那份成了 `.<area>.old/` 被刪掉。兩份都通過了各自的關卡，所以留下來的那份仍然是一份完整、自洽的假說——輸掉的只是工作量，不是正確性。

**兩個分支（或兩個 worktree）各自更新同一個 area**：area 跟著分支被 `/ship` commit。合併時 README front matter 衝突 → 衝突標記讓 front matter 解析失敗 → 腳本顯示 `過期` → 下一次 `/hypothesis` 在合併後的程式上重新走 §7。規則：front matter 永遠不手動合併，一律重新推導。blob hash 跟分支無關：兩邊最後內容一樣，hash 就一樣，不會誤判過期。

**讀者在寫入者交換的空窗讀**：兩次 rename 之間 `<area>/` 不存在。腳本看到 `.<area>.old/` 或 `.<area>.draft/` 而沒有正式目錄時顯示 `過期`，不會說「這裡沒有假說」——後者會讓 review 漏掉一份必答題。

**讀者寫 area**：結構上不會發生。腳本沒有寫檔的程式碼；review、prove-it、hunt 只叫腳本。唯一的例外窗口是讀者直接用編輯工具改 README，這條由各讀者的「只讀」規則擋，腳本擋不了（traps.md 第 3 條）。

## 跑兩次

- **`/hypothesis` 在同步中的 area 上再叫一次**：§1 走「已同步 → 只重跑」，不改任何檔案。冪等。
- **`--maintain` 跑兩次**：第二次時 blob 已經對上 → 同步中 → 只重跑。
- **`check` 跑兩次**：不寫檔，冪等；TLC 的 `states/` 暫存目錄放在系統暫存區，不放進 area（否則會被 commit）。
- **搬遷跑兩次**：第一次已經刪掉舊目錄 → 第二次找不到舊位置 → 什麼都不做。第一次停在「新的已交換、舊的還沒刪」→ 第二次看到新舊都在且新的同步中 → 只提議刪舊的。

## 停在半路

| 停在哪 | 留下什麼 | 下一次怎麼處理 |
|---|---|---|
| §2 確認規則之前或之中 | 什麼都沒寫 | 從頭 |
| §3–§5 寫模型、跑檢查 | `.<area>.draft/` | 回報有草稿；使用者說接著做就從草稿的 evidence 判斷做到哪，說丟掉就刪（草稿是這個 skill 自己的暫存，刪它可復原地重做） |
| 看過它失敗的壞版本還套著 | 只在丟棄式副本或 worktree 裡，產品程式碼沒被碰 | 副本照丟；若副本留著，下一次先清掉再開新的 |
| 交換的第一次 rename 之後 | `.<area>.old/` ＋ `.<area>.draft/`，沒有正式目錄 | 腳本顯示過期；下一次 `/hypothesis` 把草稿 rename 進去（草稿已過全部關卡才會進到交換）再刪 old |
| 交換完成、page 沒打開 | 完整 area | 只差打開，下一次叫用時重開 |
| `--maintain` 中途 | 舊 area 原封不動、同步點沒動 | 從頭維護。同步點只在交換時動，所以永遠不會出現「同步點往前移了、模型卻還沒看過它失敗」 |

## 同步點什麼時候動

只有一個時刻：§6 的交換，而交換只在 §4（看過它失敗、看過它成功）在**這一份來源**上通過之後發生。`blocked` 的維護不交換，舊同步點留著，所以那份假說繼續顯示過期——這是對的，它確實沒跟上。
