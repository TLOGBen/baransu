Harness×Model 矩陣實驗——十個 agent 團隊配置的盲評對決

同一份簡報、十組配置、雙盲評審。花最多錢跑完整流程的配置裡有一組墊底；被看好的單模型裸奔，輸在一個訊息字串上。

01為什麼做這個實驗

市面上的開發流程 skill 多半誕生於模型能力較弱的年代：先寫五層規格、再用測試先行紀律實作、每步配獨立審查。模型一代比一代強，這些鷹架照理該一層層拆掉，但拆哪些、留哪些，過去只有直覺，沒有數據。

我們把問題壓成一個 3×3 矩陣。流程軸三檔：P1 原生（什麼流程都不給）、P2 只分析（先寫規格再直接實作）、P3 分析加執行（規格、失敗測試先行、獨立審查、總驗收）。模型軸三檔：F（Fable 單模型）、OS（Opus 規劃加 Sonnet 實作）、FOS（Fable 規劃、Sonnet 實作、Opus 審查）。過程中因委派機制限制多出一格 Opus 單體，湊成十組。

三件工作刻意混搭：解析器裡的真實 bug（& 自選擇器在檢查前就被解析炸掉）、跨層功能（換源時按章節名遷移閱讀進度）、TUI 體驗改善（跨書源搜尋結果摺疊）。每組拿到一字不差的驗收簡報，在獨立 worktree 工作；十位評審只看去識別副本：沒有 git 歷史、沒有規格目錄，只有程式碼和簡報。

02計分結果

評審按四個維度打分：21 條驗收標準有沒有被測試釘死、有沒有引入 bug、架構遵循度、測試殺不殺得死突變。基本功全員過關：十組的架構分數都在 9 分以上，隱藏驗收探針全過，測試套件全綠。拉開差距的只有一件事。

03一個訊息字串抓到五組

專案資料庫的章節索引 idx 不連續：某些站點第一章落在 idx=1，因為 idx=0 被沒有連結的分卷標題佔走。這件事寫在專案文件裡，十組的規格作者也全都自己挖到了。可是「知道」和「每個輸出位置都做對」是兩回事——五組在使用者看得到的訊息裡寫出「第 {idx+1} 章」，於是畫面印出「進度重置到第 2 章：第1章 起風」，同一行字自打嘴巴。

Fable 單體踩了：它的測試 fixture 全部刻意用不連續 idx，證明它完全知道陷阱，卻在 CLI 重置訊息順手加了一。Fable 規格加 Fable 實作也踩了：規格作者和實作者是同一顆心智，作者沒想到的出錯位置，實作者同樣想不到。最慘的是 p3-os：Opus 審查員在報告裡明確描述了缺陷，然後判 advisory 放行——它自己寫的驗收條文只要求訊息包含某個子字串，審查員按字面履約，沒有打槍的依據。盲評把這個缺陷升級成全場唯一的 high。

04墊底解剖：p3-os

p3-os 付了八個 agent、五十分鐘、$11.84，拿到比 $4.92 單體更差的結果。決策日誌對出三個原因。

  • 換手損耗。單體 Opus 從發現陷阱到寫出訊息全程同一個 context；p3-os 的知識要先壓縮成規格文字再由 Sonnet 解壓，警語在壓縮時沒有升級成條文。物證：簡報給定的正規表達式 [章回節节卷] 經轉抄變成繁體「節」重複兩次、簡體「节」消失——轉抄鏈越長，抄錯機率越高，單體根本沒有這一步。
  • 責任稀釋。實作者想「條文都過了，審查會抓」；審查員想「條文沒禁止，按契約是 advisory」；總驗收想「逐項審查都通過了」。三個環節各自盡職，缺陷從契約縫隙穿過去。單體知道自己是最後一道防線，行為就不一樣。
  • 儀式性綠燈。走完全程時儀表板漂亮極了：任務全數通過審查、總驗收判定無須修補、79 個測試全綠。每盞綠燈量測的都是條文，條文鬆，綠燈只是心理安慰。
pipeline 淨值 ＝ 審查牙齒（條文可測性 × 打槍權限）－ 換手損耗（次數 × 每次衰減）。p3-os 兩頭皆輸：牙齒為零、換手最多。

05P2 的平庸與前饋兩招

只寫規格、不設審查的三組裡，成績最好的那組其實走私了一個審查環節；歸位之後，純粹的「規格加實作」只剩平庸和翻車。這種配置的保護力全部發生在實作之前，屬於前饋性質，沒有人回頭對照成品。前饋要生效，規格作者得先把危險寫進去，有效的手法就兩招。

  • 警語式（p2-os）：交接裡明寫「stop using idx+1 as a chapter number」。有效但脆弱——依賴實作者剛好讀到、記住、寫訊息那一刻想起來。
  • 表面設計式（p2-fos）：直接把訊息格式規定死：「進度已遷移：{章名}」。格式裡沒有數字欄位，錯誤在結構上無處生長。這比警語高一個檔次——把「不要犯錯」變成「無法犯錯」。

p2-f 的殘酷在於：Fable 寫規格給 Fable 自己實作，理論最強的 analyze-only 組合仍然踩雷。規格作者和實作者是同一雙眼睛照兩次鏡子，作者沒看到的表面，規格裡自然沒有，實作時照樣裸露。花 $16.45 買一份自己給自己的 checklist，輸給 $4.92 的裸奔。

06三條路

十組成績排完，可行的配置收斂成三條路，中間所有配置都付了儀式的錢而沒買到結構的保護。

07動刀方向與侷限

流程是槓桿，放大的是規格條文的品質：條文釘得死，流程把它放大成冠軍；條文鬆，流程只放大成本和縫隙。所以改革第一刀不砍流程長度，砍條文品質——每條驗收標準必須是具名可斷言的值，使用者可見的文字必須規定精確格式或明列禁止項，規格裡發現的每個資料陷阱必須同時變成條文和測試錨點。第二刀換審查員的任務書：與其全面重審，不如專掃沒有測試釘住的使用者可見表面，因為強模型的錯幾乎只長在那裡。第三刀才砍儀式：設計文件降級成一張表、逐任務上下文檔換成一段交接摘要、失敗重試上限降到一次。

實驗有邊界。三件工作對 2026 年的模型群偏簡單，十組全數達到 17 條以上釘死，天花板效應明顯；更大更難的任務可能重新拉開流程的價值差距。這份數據能定論的是中等規模、規格寫得完整的任務帶——在這個帶子裡，與其多開一個審查 agent，不如先把驗收條文寫到能拿來打槍。
