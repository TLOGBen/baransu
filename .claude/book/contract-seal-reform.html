雙塔換雙釘——十格實驗之後的改革設計

第一輪判出了冠軍與墊底；判決落定後浮出更難的問題：被告是在設計射程之外受審的。這一冊記錄改革怎麼從這個張力裡長出來——以及正在進行的驗證。

01Skill 的解剖：三種假肢

把兩個 skill 拆開看，它們同時承載三種假肢，實驗給了三種判決。知識假肢——怎麼分析、怎麼測試先行、陷阱長什麼樣——十組規格作者全部自己推導出來，已內化進模型，可以蒸發。流程假肢——五層文件、逐任務上下文檔、Red gate 儀式、DAG 編排——實測零效果，退役。注意力假肢——「現在該把陷阱寫成條文」「收尾前該開審查」——正是模型還做不到的事：p1-f 知道 idx 陷阱，fixture 全用非連續索引，卻在寫 CLI 訊息那一刻沒想起來。

這不是知識缺口，是時機缺口。結論跟著出來：skill 不會死，但身分要換——它的殘餘本體是「在正確時機喚起正確行為」的具名觸發點，一個注意力假肢，內容物從四百行流程縮到二三十行。

02contract 與 seal

改革落點是兩個微型 skill。/contract 取代 analyze：動手前先產出一頁合約——每條驗收條文具名可斷言、使用者可見文字給精確格式或禁止清單、錯不起的表面逐列配釘死測試、固定常數照抄不重打。/seal 取代 execute：宣告完成前開一個乾淨 context 的審查者，帶五行任務書——逐條驗收、掃無測試釘住的表面、跨端一致性、常數逐字比對、殺不死突變就打槍。

支撐設計的是實驗最硬的因果鏈：六個引入 bug 有五個同類，擋住它的三組各用一招——警語靠運氣、精確格式靠結構、死條文加審查靠授權。一頁合約把後兩招制度化，一次 seal 把第三招的成本從八個 agent 壓到一個。

觸發問題同時解掉：微型化讓誤觸發從三十分鐘變兩分鐘；seal 預設開啟、配機械 hook 偵測「diff 碰了表面卻沒 seal」——漏觸發從語意問題降級成機械問題。skill 名字本身是人機共享詞彙，「/contract 這個任務」六個字同時告訴雙方進入什麼模式。

03尺度外推：跨系統與 SA 文件

雙塔的設計射程另外處理。跨系統情境裡舊失敗模式全部升維：責任稀釋變成「兩側 mock 互相同意、卻都不同意現實」；常數轉抄變成 schema 靜默漂移；再加三個新怪物——context rot 讓外部記憶從冗餘變成腦本身、E2E 分鐘級回饋摧毀突變紀律、部署時序帶來相容性條文這個全新類別。

一頁紙在這裡不塞爆，它分形。關鍵換座標：系統間邊界就是彼此的 user-facing 表面，「使用者」是對面那個系統。最日常的版本是「完成前後端整頁功能、對 SA 文件宣稱完成」——SA 文件天生是鬆條文，「宣稱完成」因此是不可證偽的修辭。改革加一個 ingestion 階段：實作前把 SA 文件逐句翻譯，可斷言的進合約、隱性需求補條文或明文排除、翻譯不了的退回 SA。宣稱完成從一句話換成一包證據：條文對測試對綠燈、表面四態對截圖、schema 零漂移證明。

04三頻段路由與裸跑的價值

頻段情境形式證據狀態
小單檔、範圍明確直接實作既有共識
中單 session、跨數模組/contract 一頁合約 ＋ /seal 單次審查本輪實驗（p-min 驗證中）
大跨 session／跨系統／E2E改革版雙塔：分形合約＋邊界所有人＋編排復役外推——待第三輪雙系統實驗

裸跑在這張圖裡不是缺席的方法，是自帶性質的方法。它是量尺：沒有 $4.92 的對照組，模型原生就會的東西全會記進流程的功勞簿。它有結構防護：四大失敗模式裡的轉抄鏈和責任稀釋，在單一心智全責下根本不存在。它是校準儀：模型每換一代，定期裸跑是唯一能測出「又內化了什麼、哪些鷹架該拆」的儀器——不做定期裸跑的 plugin 必然單調增肥，因為減法永遠拿不到證據。

05選用會不會選對

誠實答案：不會總是選對，而且無法讓它總是選對——選用是模型讀 description 做的語意判斷。改革換了目標：不追求選得準，追求選錯很便宜、選漏抓得到。

  • 微型化改變錯誤成本的不對稱——誤觸發從三十分鐘的五層規格，變成兩分鐘的一頁紙
  • 觸發條件過可斷言性閘門——「跨 session？碰 user-facing 表面？」是可觀測特徵，「任務夠不夠大」不是
  • seal 預設開啟＋機械 hook 後盾——「diff 碰了表面卻沒 seal」用 grep 就能判，hook 敲鐘、不做決定
  • 頻段詞彙縮到三個詞——小＝直接做、中＝/contract、大＝/analyze；人腦路由在邊界上永遠比模型可靠
  • 選用決策納入遙測——誤觸發率按月回看，餵給演化迴圈修 description

06驗證輪：大膽舉動、小心測試

改革不空談。三個驗證 arm 在原基線、原簡報、原盲評協定上開跑：p2-os′ 測改革後規格（可斷言性閘門、陷阱昇華、常數塊、表面清單）的純前饋上限；p3-os′ 測死條文加窄域審查任務書能否讓原墊底配置翻身；p-min 直接下注無 skill 世界——Opus 一頁合約、Sonnet 實作、Opus 單次審查，三個 agent 零管線。

類別滅絕證據：idx+1 章數缺陷在三格中零出現（第一輪 5/10），常數轉抄缺陷零出現（regex byte-diff 全乾淨，含「节／節」）。條文改革對這兩個錯誤類別是結構性消滅，不是機率性壓低。三位盲評也全數再度標記了 pre-existing 的 reader idx 缺陷——backlog 首位不變。
