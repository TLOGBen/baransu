# P4 — E3、E1：同一次回應裡載入兩個 skill，其中一個的卡片整張不見

害處：模型平行叫兩個 skill（例如 `/lint` 和 `/review`）時，其中一個的結果卡片既不在它那次 Skill 呼叫底下，也不在輸入框上方，你完全看不到。

1. 模型在同一則回應裡送出兩個 Skill 呼叫：`tu-1` 載入 `baransu:lint`，`tu-2` 載入 `baransu:review`，兩個都在任一個 skill 載入之前開始。
2. `tu-1` 進入 `adapters/claude-code/hooks.ts` 的 `tool.call` hook，呼叫 `lint.skillCalling('tu-1')`，寫進 `$.state` 的 `skillCall`。
3. `tu-2` 也進來，呼叫 `lint.skillCalling('tu-2')`，把同一個 `skillCall` 蓋掉。
4. 兩個 skill 各自載入，`engine.ts` 的 `skillPrompt` 都拿當下的 `S().skillCall` 當作卡片要掛的呼叫；每次呼叫結束時，`finally` 又把 `skillCall` 清成 `undefined`。

觀察到的結果（檢查器 `view-judge.test.ts`「E3 two Skill calls at once」）：`tu-1` 底下是 `/lint` 的卡片，`tu-2` 底下沒有卡片，輸入框上方也是空的；`/review` 的卡片不在任何地方。

這份檢查只確定了結果，沒有追到第 4 步裡哪一次寫入蓋掉了它。

根源：所有 Skill 呼叫共用一個 `skillCall` 欄位。`skill.prompt` 事件本身不帶呼叫編號，但帶 skill 名稱，而 Skill 呼叫的 `tool.call` 也帶 skill 名稱，可以用名稱對回呼叫。
