# P11 — E8、E9、E11、R1：刪除預覽第二次放行，畫成純文字並叫你「再下一次」

害處：東西已經刪掉了，卡片還寫「確定沒錯，再下一次同樣的指令」，像是還沒執行；而且是一段純文字，不是設計稿的分組路徑清單。（使用者 2026-11-04 在真的 session 裡截圖看到。）

（檢查器 `pre:bash delete check` 判出 E8、E9、E11、R1；第二推導第 1、2、4(a) 項找到同一條路徑。）

1. preset 的 `destructive-preview`，等級 `check`，`message` 是「先看上面列出會動到的東西；確定沒錯，再下一次同樣的指令」（`skills/lint/preset/sets/runtime.toml`）。
2. 第一次 `rm -rf build`：`callAfterTake` 走 hold-once，`refuse({... withPreview(pre) ...})`，卡片「先確認會動到的東西」帶 `paths`，畫成分組清單。這一步是對的。
3. 下一個回應再送一次：hold-once 跳過，指令執行（同 P10 第 3、4 步），預覽那條發現進了 `inline` 和 `context`。
4. 動作之後的卡片走 `summarize(..., inline)`，不經過 `withPreview`，所以沒有 `paths`；預覽整段（含 message 的「再下一次」）成了一行發現文字。`view/card.ts` 的 `drawCard` 看到 `d.paths` 是空的，就照文字畫。

結果：已執行的呼叫底下，有一張寫著「再下一次同樣的指令」的純文字卡片；模型也再收到一次整段預覽。

根源：同 P10；另外寫卡片有兩條路（擋下用 `withPreview`、放行用 `summarize`），只有擋下那條會把預覽轉成路徑清單。
