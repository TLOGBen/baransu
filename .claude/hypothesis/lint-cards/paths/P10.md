# P10 — E9、R1：擋過一次的 `check`，第二次放行時又畫一次、又講一次

害處：你和模型都已經看過的提醒，在動作真的執行時又出現一次，畫面多一張重複的卡片，模型也再讀一次。

（檢查器 `model/card-content.test.ts` 的 `pre:edit edit check`、`pre:bash bash check`、`pre:commit commit check`、`pre:push push check` 在真程式上判出；第二推導只在刪除預覽上找到同一個根因。）

1. 一條 `pre:bash`（或 `pre:edit`、`pre:commit`、`pre:push`）的 check，等級 `check`，第一次送出時有發現。
2. `engine/engine.ts` `callAfterTake`：`settle()` 依 `engine/timing.ts` 的 `PRE.check = v('hold-once', 'line')` 得到 `gate = 'hold-once'`，動作被擋下，卡片「先確認一次」掛在這次呼叫底下。這一步是對的。
3. 下一個回應送出同樣的動作：`S().held` 裡有它、而且 `seen.step < at.step`，所以 `if (s.gate === 'hold-once')` 那段跳過，動作執行。
4. 同一條發現仍在 `s.line` 裡（`settle` 把 tell 是 `line` 的每條都放進去）。`const plain = s.line.filter(...)`、`inline.push(...plain)`、`context.push(render(..., plain))`。
5. 動作之後：`keepCard(S(), e.id, summarize('指令前', inline, ...))`，第二張卡片（`note`，「lint · 指令前」）寫著同一條發現；`notes` 把同一段話再交給模型。

結果：同一個動作的同一條發現，出現在兩張卡片上，模型也收到兩次。

根源：`check` 的意思是「擋一次，看過就放行」，但放行時沿用的是 `PRE.check` 的 tell `line`，沒有記得這條已經在擋下時交代過。
