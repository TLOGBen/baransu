# P8 — E4：訊息沒真的送出，輸入框上方的卡片卻先被清掉

害處：你送出的訊息被別的 plugin 或設定擋下、沒有真的進到對話時，輸入框上方的 lint 卡片已經先不見了，你沒機會看到。

（第二推導 E4-b 找到；檢查器「E4 a message that never enters」在真程式上確認。）

1. 輸入框上方有一張卡片（例如一輪要結束時被擋下的卡片）。
2. 你送出訊息 → `prompt.submit` → `engine.ts` 的 `promptSubmit`，在拿走欠的東西之前，同步執行 `S().band = []`。
3. 下層的 hook 回傳 `{ drop }`，訊息沒有進到對話；`submitAfterTake` 依 `droppedPrompt` 呼叫 `taken.giveBack()`，只把 slips 和 queued 還回去，band 沒有還回去。

結果：訊息沒送出，卡片卻已經清掉了。

根源：清 band 的時機是「收到訊息」，不是「訊息真的進到對話」。
