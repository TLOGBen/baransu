## 一句話

`_shared/optimization.md` §2 是「被要求最佳化時要走的路線」：先建模，判斷有沒有被要求，判斷是哪幾類，決定怎麼拆，求解，合回去重驗，再交出。這份假說檢查的是這份文件：照它走，會不會交出一個說是「最佳」其實不是的結果、一個答案變了的版本，或者一個沒被要求的最佳化？

## 這份假說找到、並且已經修掉的問題

第一次跑就在 `optimization.md` 裡找到 6 處漏洞，兩種方法各抓到一部分，全部當場修掉。修正前的寫法留在 `variants/`，當作「看過它失敗」的證據：

| 怎麼發現的 | 問題 | 修法 |
|---|---|---|
| 模型檢查器（`variants/R1-LooseWording.cfg`，8 步） | 第 6 步把「差距」也列成一種證明，附上「差距 2」也能說成「最佳」 | 只有差距為 0 才能說最佳；其他證明說的是「差多少」，只能照那樣報告 |
| 模型檢查器（`variants/R1-AtBoundPerPart.cfg`，7 步） | 每一部分都在自己的下界上，就說整體「已經是最佳」；但耦合的拆法，或後面會改變前面的拆法，各部分最佳不代表整體最佳 | 「已經是最佳」只用在整個問題的下界上，或拆法保得住最佳時 |
| 不可能清單的反駁 | 「不適用的步驟一句話帶過」也能套用在重驗上 | 只要有任何改變，重驗就不能跳過 |
| 不可能清單的反駁 | 答案不同的版本只說是 bug，沒說不能交出 | 不交出，退回求解 |
| 不可能清單的反駁 | 重驗的容差由路線自己訂，可以事後放寬讓新版本過關 | 容差在最佳化之前依使用者需求訂好、寫明理由，之後不准放寬 |
| 不可能清單的反駁 | 沒有明寫「交出」的時機 | 只有通過重驗的版本才交出，並附上證明了什麼 |

另外，反駁也找出模型抽得比文件嚴格的兩處，模型已經照文件修正：結論多了「局部最佳」和「不知道下界」兩種說法；同一個問題的不同部分可以用不同的拆法。

## 範圍

- 一個被要求的問題，拆成兩部分；每部分是可分離、有先後、耦合、不可拆四種之一；差距是 0、大於 0 或不知道；新版本答案一樣或不一樣。
- 前提 A1：每一類自己的重驗方法，看得出答案不同。
- 不涵蓋：類別本身選得對不對（第 3、4 步只透過差距與說法影響結果）；量測本身準不準。
- 窮舉的結論只在這個範圍內成立。

- **工具**：TLA+，TLC2 2.19。
- **指令**：`python .claude/hypothesis/optimization-route/model/check.py <tla2tools.jar>`，11 項檢查，最多 1256 個狀態。
- **看過它失敗**：R1 由兩種修正前的寫法打破；R2 由拿掉重驗打破（`variants/R2-NoRecheck.cfg`）；R3 由拿掉「有沒有被要求」的判斷打破（`variants/R3-NoAskGate.cfg`）。
- **看過它成功**：G1、G2 都做得到；拿掉「交出」就都走不到（`variants/G1-NoDeliver.cfg`、`variants/G2-NoDeliver.cfg`）。
- **看過它像程式（未完成）**：
