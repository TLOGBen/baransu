# P1：hook 在回答前就斷掉，需要先預覽的刪除被直接執行（C4／R11 被打破）

TLC 的最短路徑（`model/traces/design-c4.txt`，共 3 步），翻成實際會發生的事：

1. 模型在這一輪第一次要求刪除。這個動作需要「先擋一次、給預覽」（`destructive-preview`，等級 `check`）。Codex 觸發 `PreToolUse`，啟動一支新的 hook 程式（`Start("pre1")`）。
2. 這支程式還沒回答 Codex 就斷了（`Kill("pre1")`）。可能是 Codex 的逾時把它殺掉、Node 啟動失敗，或在等鎖時放棄（`GiveUp`，另一條同樣長度的路徑）。
3. Codex 把 hook 失敗當成放行（PoC Q10：逾時後工具照常執行），刪除就被執行了。模型從來沒看到預覽。

**造成的傷害**：使用者設定成「刪除前一定先預覽一次」的動作，在 hook 出事的那一次，連一次預覽都沒有就執行了。

**這不是 Codex 才有的**：Claude Code 的 hook 逾時同樣會被跳過，`lint-mod-state` 已經把它列為接受的邊界。Codex 多出來的是會走到這條路的原因：Node 找不到、每次呼叫都要啟動一支新程式、等鎖時放棄。

**為什麼修不到理想**：C5（hook 出事時不准擋使用者）和這條規則在這一點上正面衝突，而且放行是 Codex 自己決定的（PoC Q10），adapter 管不到。能做的只有減少走到這條路的機會，見 README 的〈差距〉。

重播：TLC `python check.py design-c4`。實際在 app 上重播，請交給 `/prove-it`：讓 `PreToolUse` 的 hook 在第一次刪除時故意 `sleep` 到超過 `timeout`。
