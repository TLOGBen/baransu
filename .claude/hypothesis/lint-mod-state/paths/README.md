# 出錯路徑（8.37.0 commit 時的 lint.ts，修正前）

每條路徑都有一個引擎測試（`claude plugin test` 用的 `lint.test.ts`，P1–P10）：在修正前的 mod 上紅、修正後綠。P10 對應的「交代現況」在 8.37.0 還不存在，它防的是這次修改中途出現過、從沒發布的版本。

## P1 — R1：subagent 的指令吃掉主迴圈待重述的段落
1. 使用者用中文說話（prompt.submit 記下語言）。
2. 主迴圈寫了一段英文給使用者（session.append：languageSlip 記下這段）。
3. subagent 跑一個 Bash（tool.call 帶 agentId：沒有附提醒，但 `languageSlip = undefined` 照樣執行）。
4. 使用者下一則訊息：沒有任何重述要求。
害處：寫錯語言的那段永遠沒被重新說。

## P2 — R1：被擋下的呼叫丟掉重述要求
1. 主迴圈寫了一段英文。
2. 主迴圈下一個指令被別的規則擋下（例如 force push），或被刪除預覽暫停。
3. 重述提醒只附在成功的結果上，而待重述的紀錄已經清掉。
害處：同上。

## P3 — R2：兩個平行指令各要求一次重述
1. 主迴圈寫了一段英文。
2. 同一則訊息裡兩個 Bash 平行執行；兩個 tool.call 都在 `await` 之後才清掉 languageSlip，兩邊都看到同一段。
害處：同一段被要求重說兩次。

## P4 — R1、R4：slash command 的訊息帶不到「重新」
1. 主迴圈寫了一段英文（或這一輪做了事卻沒交代）。
2. 使用者下一則是 slash command（`/baransu:ship …`）：prompt.submit 對 `e.command` 整段跳過。
害處：重述和交代的要求都沒送出；使用者先打 slash command 時，連語言都學不到。

## P5 — R6：上一輪放行的刪除，這一輪直接執行
1. `rm -rf build` 被預覽暫停，再下一次放行。
2. 下一輪（或在 subagent 預覽過之後）同一串指令：previewed 永不清空，直接執行。
害處：目錄內容可能已經不同，卻沒有再看一次。

## P6 — R7：同一串刪除指令，在另一個目錄刪到沒預覽過的東西
1. 在 repo 根目錄 `rm -rf dist` 預覽、放行。
2. 另一個 Bash 呼叫 `cd packages/app`。
3. `rm -rf dist`：字串相同，直接執行，刪掉 `packages/app/dist`。
害處：刪掉從沒列出過的東西。

## P7 — R8：用 Bash 寫檔不算改檔
1. 用 Edit 改檔，跑測試。
2. 用 `sed -i` 再改一次檔：被記成「指令」，改檔序號不變。
3. `/ship` 的收尾紀錄說「改檔後跑過指令」，實際上最後一次改檔之後什麼都沒跑。

## P8 — R9：mod 重新載入後，收尾紀錄說「沒有改檔」
1. 改過檔。
2. mod 重新載入（模組變數歸零）。
3. `/ship` 的收尾紀錄：「這個 session 沒有改檔」，提醒降成附註。

## P9 — R10：一輪中途重新載入，沒說明就動手也不會被標出
1. 一輪開始（「這一輪說過話沒」設成否）。
2. mod 重新載入（初始值是「說過了」）。
3. 第一個動作前沒有任何文字，卻沒被標出。

## P10 — R5：交代完又更新計畫，被要求再交代一次（修改中途的版本）
1. 做事、寫完整的交代。
2. 接著呼叫一個不改檔的工具（更新計畫、TodoWrite）：「交代後的文字」被歸零。
3. 一輪結束：判定沒交代，下一則訊息又要求交代。
