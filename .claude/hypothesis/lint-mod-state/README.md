# 假說：lint mod 的跨事件狀態，在任何事件順序下都照它的承諾提醒

- **使用者要拿它做什麼**：決定 lint mod 能不能直接 ship、信任它的「重新」「刪除前預覽」「收尾紀錄」，不必在每個 session 裡盯著它有沒有漏報或亂報。
- **理想**：主迴圈該被提醒的事，每一件都恰好提醒一次；不該提醒的（subagent 的動作、已經交代過的一輪）一次都不提醒；任何事件順序下都一樣。
- **已證明**（往上推）：修正後的模型在範圍內（MaxSteps 7、2 段寫錯語言的文字、2 個刪除指令、2 個同時進行的主迴圈呼叫、2 個目錄）守住全部 10 條規則；修正前的程式在同一範圍內打破 R1–R10 全部（R3 只在獨立推導的寬讀法下，見下）。依據：TLC，見界與證據。
- **最好可能**（往下壓）：理想本身——修正後的模型達到了。
- **差距**：在範圍內「相遇」；範圍外（更多步、更多同時呼叫）只靠論證，見界與證據。
- **主張與量詞**：在所有事件順序下（turn.start、prompt.submit、session.append、主迴圈與 subagent 的 tool.call、turn.complete、skill.prompt、mod 重新載入任意交錯）
- **規則確認**：已確認（使用者 2026-11-02；讀法 D1 選 B、D2 選 A）
- **涵蓋的對象**：`plugins/baransu/hooks/lint.ts` 的狀態物件 `S`（`restore`、`persist`）與讀寫它的 hook：`prompt.submit`、`turn.start`、`session.append`、`tool.call`、`turn.complete`、`skill.prompt`；型別 `plugins/baransu/types/index.d.ts`
- **描述的版本**：8.37.0 的修正版，含複查後的第二輪修正（lint.ts sha256 `245c8e4d64ff…`）

## 獨立推導

第一次（封存到驗證才打開）：十條全部打破，其中 6 類是模型漏掉的路徑（見 Q3），已補進模型並修正程式。不採用為違規的：subagent 跑的 `/review` 算 review、review 中途中斷也算 review（記為邊界）。
修正後的複查（第二位讀者只讀 lint.ts 與型別）：R3 守住，R10 有一個小缺口，其餘八條各找到模型外的破法。都在模型的抽象之下（hook 失敗、下層擋下、不開回合的 slash command、回合中途送出的訊息、中文字數、背景指令、與 subagent 同時改檔、還沒有 lint 時的改檔、兩種 shell 的目錄、刪除指令的寫法），模型的結論不變；程式已修：

| 規則 | 破法 | 處理 |
|---|---|---|
| R1、R4 | 取走後 hook 失敗或被下層擋下，提醒丟了 | 放回；取走後立刻存檔 |
| R1、R4 | `/cost` 這類不開回合的指令取走提醒 | 只有會送進模型的訊息才取走 |
| R4 | 回合中途送出的訊息早於欠帳產生 | 欠的交代也跟著下一個主迴圈指令送出 |
| R2 | 取走後、存檔前重新載入，同一批送兩次 | 取走後立刻存檔 |
| R5 | 中文短交代不到 60 字母 | 一個漢字算兩個 |
| R6 | `git rm`、`bash -c 'rm …'`、`rd`、`rimraf` 認不出來 | 都會預覽 |
| R7 | 子殼層 `( cd … )`、兩種 shell 共用目錄 | 看穿括號；Bash 與 PowerShell 分開追蹤 |
| R8 | 背景指令算跑過；指令期間 subagent 改檔 | 背景不算；用指令開始時的改檔序號 |
| R9 | 建 lint 之前的改檔沒算 | 沒有 lint 也計數 |
| R10 | 第一個動作被擋下後就不再標 | 改由串流文字判斷「說過話」 |

引擎測試 Q1–Q4（`/cost` 不取走、欠的交代跟著指令、`bash -c` 的刪除被預覽、背景指令不算）連同 P1–P10 共 31 個全綠。

記為邊界（不修）：`~`、`$` 無法展開，只標明；`find -delete`、`xargs rm` 無法事先列出，暫停一次後放行；同一則訊息裡兩個相同的刪除，第二個會放行；MCP 寫檔工具不算改檔；hook 逾時被跳過；`warn` 不擋；交代後又跑指令要再交代一次；subagent 跑的 `/review` 算 review。
